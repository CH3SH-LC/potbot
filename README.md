# potbot

面向 Android 的**任务式智能体交互层**：以唯一自然语言入口接收用户目标，按需组织临时智能体群组协作，交付真实可编辑文件，并在涉及外部动作时要求用户逐次确认。

本文件只描述**技术设计**。构建与使用见 [USAGE.md](USAGE.md)。

---

## 1 设计立场

三条贯穿全局的约束，其余设计都由它们推导出来。

**1.1 业务内核在设备侧。** 任务调度、角色、模板、记忆、共享事实、密钥与文件处理都在手机本地执行。不把可配置的远程后端当作正式运行路径——远程只用于模型推理与已获授权的第三方业务接口，二者都是联网服务，不要求把模型权重装入设备。

**1.2 内核必须可复现。** `src/**` 不使用墙钟、随机数、进程信息与文件系统；所有非确定性来源必须由调用方**注入**。这不是风格偏好，而是为了让「同一输入 ⇒ 同一字节」可以被测试断言。

**1.3 不确认即不宣称。** 任何外部动作只有拿到**读回证据**才算完成；没有回执一律记为未知，且未知状态必须可恢复、不可自动重放。

## 2 分层

```
┌──────────────────────────────────────────────┐
│ UI（WebView，本地资产 file:///android_asset） │
└───────────────┬──────────────────────────────┘
                │ 窄接口：submit / subscribe / cancel（含调用方与 origin 校验）
┌───────────────▼──────────────────────────────┐
│ Android 宿主：前台服务、事件下行、生命周期恢复  │
└───────────────┬──────────────────────────────┘
                │
┌───────────────▼──────────────────────────────┐
│ 业务内核：调度 · 角色 · 模板 · 记忆 · 共享事实  │
└───────────────┬──────────────────────────────┘
                │ 端口（全部以 TypeScript 接口冻结）
┌───────────────▼──────────────────────────────┐
│ StoragePort · ModelPort · FactsPort          │
│ OfficePlugin · ConfirmAction · ExternalReceipt│
└──────────────────────────────────────────────┘
```

**关键设计**：UI 只能通过受限本地桥与宿主通信，桥不接受任意文件路径、密钥或代码执行请求。页面来源受白名单约束（本地资产来源在列，任意远程来源不在列），因此页面无法把宿主变成通用代理。

**输出通道不阻塞输入**：宿主把模型与工具事件以单向下行推给页面；页面发起的命令是幂等的（`commandId` + `idempotencyKey`），重复投递返回原结果而非重放副作用。

## 3 契约（`contracts/mobile-v1/`）

契约是**机器可读且可独立校验**的：版本化 JSON Schema、状态词表、正/反例 fixtures，以及一个零依赖校验器。跨模块对接以同一份契约为准，避免各自猜测接口。

| 接口 | 设计要点 |
| --- | --- |
| 命令与事件 | `schemaVersion / commandId / operation / idempotencyKey / payload`；对已有对象的修改必须带 `expectedRevision`，旧修订明确冲突；事件带 `seq / revision / status / resultRef` |
| ModelPort | 流式 text / tool-call / usage / error；**工具结果必须与调用 ID 对应**；取消、超时、预算皆为端口内的显式状态，失败绝不产生成功 |
| TemplateManifest | `id / version / capabilities / schemas / permissions / runtimeCompatibility / migration / probe`；安装、启用、授权、端口就绪**四态分离**，状态只来自真实探针 |
| OfficePlugin | `import / create / inspect / apply / preview / export / undo / redo` → `artifactId / revision / digest / mime / changedObjects / warnings / receipt` |
| StoragePort | 原子事务、blob 读取、流式写入、SHA-256、版本 CAS、content URI；**不得返回宿主机绝对路径** |
| ConfirmAction | `actionId / accountRef / taskRevision / paramsDigest / quoteRef / amount / currency / expiresAt / scope` |
| ExternalReceipt | `prepared / authorized / submitting / submitted / unknown / confirmed / failed / cancelled`；取消需有供应方语义 |

### 一次性授权与恢复

外部动作走**一次性授权**：授权对象绑定动作、账号、任务修订、完整参数摘要、报价、金额与币种、期限与权限范围。原生确认页从持久账本读取金额与地址，**不信任模型或页面提交的展示字符串**——展示与执行读同一份账本记录，二者不可分叉。

提交前**原子占用**授权并写 submission 记录；撤权、过期或参数变化一律拒绝。提交结果未知时，恢复原 submission 并查询原单，**不另发授权、不重复下单**；崩溃发生于「已占用、未发出」也由该记录辨明状态。

## 4 内核纪律（可机器化断言）

`src/**` 的约束被写成测试而非口头约定：

- 除具名 IO 适配器外，不出现 `node:fs` / `node:zlib` / `node:child_process`；内核不依赖任何运行期第三方包。
- 代码文本不含 `Date.now(` / `new Date(` / `Math.random(` / `process.pid` / `toLocaleString` 等非确定性 token——**时间与随机必须注入**。
- 源码树不得含裸 NUL 与控制字节（否则文件被工具链判为二进制）。
- 派发前缀表由路由**现推**，新增路由自动纳入守卫，不靠手写清单。

这些规则的价值在于：它们把「内核可复现」从设计意图变成**会让构建失败的约束**。

## 5 Office 文档引擎

三类文档共用同一套设计原则。

**保部件往返。** 导入既有文档时，未改动的部件**逐字节保持**；无法建模的节点保留原状而非静默丢弃。判断标准是字节而非「语义等价」——「回到包里」不等于「字节不变」，因此另有审计器逐部件、逐关系、逐内容类型比对原件与另存件，并明确报告哪些部件被**重建**。

**损坏输入显式拒绝。** 容器层与包层分别归类拒绝原因（截断、CRC 不匹配、路径穿越、缺失必需部件、关系悬挂、重复关系 id、共享公式无主等），未知错误**向上抛**而不是吞掉；同时给出「可读但不规范」的告警。

**排版与可编辑性分开验收。** PDF/图片用于视觉校验，可编辑性由文档本身校验；**不用 PDF 截图替代 DOCX 可编辑性的证据**。

## 7 设计取舍

**为什么把纪律做成测试。** 「不要读墙钟」这类规则靠评审守不住；一旦成为会让 CI 变红的断言，它就不可回退。

**为什么契约先行。** 多个模块并行开发时，先冻结 `contracts/` 的字段与状态词表，各模块按同一份 SHA 实现，避免互相等待和接口猜测；改字段走新增可选字段或版本升级。

**为什么修文档要动到「能否重算」而不仅是「能否打开」。** 表格运算、页码、目录缓存都必须由本机真实计算得出，不依赖消费端刷新，否则「打开能看」会掩盖「本机并未真正算出结果」。

**为什么外部动作要一次性授权而非长期授权。** 金额、地址、参数摘要与任务修订共同构成授权边界；任一项变化即失效，可以把「用户当初同意的是什么」精确固定下来。
